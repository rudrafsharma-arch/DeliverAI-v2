Step‑by‑Step Instructions

Prerequisites

  • BTP CLI btp version 1.21.0+ installed.
  • Active login token with cloudfoundry.admin or accounts.admin scope.
  • Global Account ID and Subaccount ID (if needed). Example: ga-12345678-90ab-cdef-1234-567890abcdef.
  • API key for Accounts Service if using API calls.

1. Login and Target the Environment

btp login --subaccount-id ga-12345678-90ab-cdef-1234-567890abcdef
btp target -g global-account-id -s subaccount-id
btp target --current

2. List Activated Services via CLI

btp list services

This command returns a table in the CLI; redirect to a file if desired:

btp list services --output csv > services.csv

3. Retrieve Service Instances via Accounts Service API

Endpoint: GET https://api.globalaccount-id.hana.ondemand.com/api/v2/serviceInstances

Example cURL:

curl -X GET "https://api.globalaccount-id.hana.ondemand.com/api/v2/serviceInstances" \
     -H "Authorization: Bearer ACCESS_TOKEN" \
     -H "Accept: application/json" \
     -o service_instances.json

  2. Status Validation: Ensure each instance shows Active in both CLI and Cockpit.
  3. For HANA Cloud, run cf ssh hana-instance -c "hdbsql -U SYSTEM -d SYSTEM -i 0 -c 'SELECT 1' " and confirm a successful query.
  4. Latency & Uptime: Use cf app <app-name> to ensure the app routing (via Service Registry) is healthy.
  5. Destination Connectivity: From a Cloud Foundry app, call a destination to verify correct configuration.

Troubleshooting

Common Issues

CLI command not found
Ensure BTP CLI is in your $PATH and install npm install -g @sap/btp-cli if missing.
Authorization errors on API call
Verify the token has cloudfoundry.admin scope. Refresh token if expired.
Service instance missing in CLI output
Check that the target subaccount is correct: btp target --current. Services might be in a different space.
Health check fails for HANA Cloud
Confirm network connectivity via cf ssh hana-instance and verify the HANA user has HDB_ADMIN privileges.
