Executive Summary

  • Assessment of existing connectivity configuration.
  • CLI and API commands to test connectivity.
  • Verification steps and troubleshooting.
  • Recommendations for trial, sandbox, and production environments.

Action Plan

  1. Validate the Cloud Connector is up‑and‑running.
  2. Retrieve destination metadata and inspect connectivity status.
  3. Use the BTP CLI to perform a direct connectivity test.
  4. Verify via the SAP BTP Cockpit connectivity dashboard.
  5. Document findings and resolve any issues.

Step‑by‑Step Instructions

1. Verify Cloud Connector Health (Web Interface)

  1. Log into the SAP BTP Cockpit.
  2. Navigate to Connectivity → Cloud Connector.
  3. Check the health indicator (green ✔). Click View Details for logs.

2. Verify Cloud Connector Health (API)

curl -k -u <client-id>:<client-secret> \
     https://<subaccount>.hana.ondemand.com/api/cloudconnector/v1/status

Expected response snippet:

{
  "status": "OK",
  "timestamp": "2026-10-26T10:30:00Z",
  "components": {
    "cloud-connector": {
      "health": "Healthy",
      "message": "All tunnels operational"
    }
  }
}

3. Retrieve Destination Metadata

curl -k -u <client-id>:<client-secret> \
     "https://<subaccount>.hana.ondemand.com/api/destination/v1/destinations?name=MY_ONPREM_SYSTEM" | jq .

Key fields to inspect:

  • name
  • type – should be HTTP or RFC
  • description
  • proxyType – OnPremise
  • connectivityStatus – OK / FAIL

4. Test Destination Connectivity (Direct Call)

curl -k -H "X-Requested-By: my-app" \
     "https://<subaccount>.hana.ondemand.com/api/destination/v1/destinations/MY_ONPREM_SYSTEM/connectivity" \
     -u <client-id>:<client-secret>

Sample successful response:

{
  "status": "OK",
  "message": "Connectivity established",
  "lastTest": "2026-10-26T10:45:00Z"
}

5. Use BTP CLI for Connectivity Check

  1. Open terminal and log into your BTP account:
btp login --subaccount <subaccount-id> --region eu10
  1. Check Cloud Connector status via CLI (if available):
btp cloud-connector status

Output example:

Cloud Connector Status: Healthy
Tunnels: 3 (Active)
  1. Run a connectivity test for a destination:
btp cf env --json --destination MY_ONPREM_SYSTEM

Result should include "X-CB-Connectivity: OK".

6. Verify via SAP BTP Cockpit

  1. Navigate to Connectivity → Destinations.
  2. Select MY_ONPREM_SYSTEM and inspect the Connectivity Status tile.
  3. Click Test Connection to trigger an on‑demand test.
  4. Confirm the status updates to Success.

7. Troubleshooting and Remediation

If any component shows FAIL or Unhealthy, proceed with the troubleshooting steps described in the Troubleshooting section.

Verification Steps

After performing each action, use the following checks:

  1. CLI Output – Confirm status messages contain OK or Healthy.
  2. API Response – Validate JSON includes "status": "OK" or "health": "Healthy".
  3. Cockpit Dashboard – Green indicators with Success status.
  4. Log Inspection – Look for ERROR entries in Cloud Connector logs via btp cf logs <cc-instance>.
  5. Certificate Verification – Ensure the certificate chain is valid with openssl s_client -connect <cc-host>:443.

Troubleshooting

Issue Root Cause Remediation Verification
Cloud Connector shows Unhealthy Missing or expired certificate Upload new certificate via BTP Cockpit or CLI: btp cloud-connector upload-certificate --file mycert.pem Re‑check status; should be Healthy
Destination connectivity FAIL Incorrect proxy configuration or missing tunnel Verify proxyType=OnPremise and that the corresponding tunnel is active. Run btp cf env to see X-CB-Connectivity: OK
API call returns 401 Unauthorized Client credentials not stored or invalid Regenerate client id/secret via BTP Cockpit > Service Keys and update CLI config. Retry curl command; should return 200.
Connectivity test times out Network latency or firewall blocks Check on‑prem firewall logs; allow outbound to *.hana.ondemand.com and Cloud Connector host. Test again; timeout should reduce.
Certificate expiry warning Certificate nearing expiration Renew and upload new certificate. Check openssl s_client output for notBefore and notAfter.

Responsible AI & Security Considerations

Security Best Practices:

  • Never embed client IDs or secrets in source code.
  • Store secrets in the SAP BTP Credential Store or a secure vault.
  • Use short‑lived tokens (client credentials grant) when accessing APIs.
  • Rotate certificates and keys quarterly.

Responsible AI: Ensure that any data retrieved via destinations or integration flows complies with your organization’s data governance policies. Do not expose sensitive data in logs.
