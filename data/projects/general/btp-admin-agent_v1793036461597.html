List All Activated Services on SAP BTP Account – Draft Report

1. Executive Summary

This document provides a detailed, step‑by‑step guide to retrieve a comprehensive list of all activated (service‑instance) services in your SAP Business Technology Platform (BTP) account. It covers:

  • Assessment of current activated services.
  • Methods to retrieve the list via the BTP CLI and the BTP Accounts Service REST API.
  • Verification steps to confirm that the data is accurate.
  • Best‑practice recommendations for handling sensitive credentials.
  • Potential troubleshooting tips.

All examples are in DRAFT status and intended for a Production environment, but can be adapted to Trial or Sandbox settings by adjusting endpoint URLs and API scopes accordingly.

3. Action Plan

  1. Obtain an OAuth 2.0 access token from the BTP Accounts Service.
  2. Call the /v1/subaccount/{subaccountId}/service-instances endpoint to fetch all service instances.
  3. Filter the results to those with state: "ACTIVE" or plan: "PROD" as required.
  4. Alternatively, use the BTP CLI cf services command for a quick local overview.
  5. Verify the returned data against your internal catalog.

4. Step‑by‑Step Instructions

4.1 Generate OAuth 2.0 Access Token (Client Credentials Grant)

Use the BTP Accounts Service token endpoint:

POST https://accounts.eu10.hanatrial.ondemand.com/api/token
Headers:
  Content-Type: application/x-www-form-urlencoded
Body:
  grant_type=client_credentials
  client_id=<client_id>
  client_secret=<client_secret>
  scope=accounts.subaccount.read

Sample CURL command:

curl -X POST "https://accounts.eu10.hanatrial.ondemand.com/api/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials" \
  -d "client_id=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" \
  -d "client_secret=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" \
  -d "scope=accounts.subaccount.read" -s -o token.json

The token.json will contain:

{
  "access_token":"eyJraWQiOiJr...",
  "token_type":"Bearer",
  "expires_in":3600
}

4.2 Call the Service Instances API

Endpoint:

GET https://accounts.eu10.hanatrial.ondemand.com/api/accounts/v1/subaccount/{subaccount_id}/service-instances?fields=id,service_name,plan,state,creation_time

Replace {subaccount_id} with your actual sub‑account ID.

Sample CURL command:

curl -X GET "https://accounts.eu10.hanatrial.ondemand.com/api/accounts/v1/subaccount/7f3a8b1c-2e5d-4f9c-8b2e-9a0c1d2f3e4b/service-instances?fields=id,service_name,plan,state,creation_time" \
  -H "Authorization: Bearer $(jq -r '.access_token' token.json)" \
  -H "Accept: application/json" -s -o services.json

4.3 Parse the Result

The services.json will be a JSON array. Use jq to filter active services:

jq '.[] | select(.state=="ACTIVE") | {id,service_name,plan,creation_time}' services.json

Example output:

{
  "id":"ab12cd34-ef56-78gh-90ij-klmnopqrstuv",
  "service_name":"HANA Cloud",
  "plan":"PROD",
  "creation_time":"2024-04-01T12:34:56Z"
}
{
  "id":"cd34ef56-gh78-90ij-klmn-opqrstuvwx12",
  "service_name":"Integration Suite",
  "plan":"PROD",
  "creation_time":"2024-02-15T08:22:10Z"
}

4.4 Alternative: BTP CLI

Log into the BTP CLI if you have it installed:

bx login -a https://accounts.eu10.hanatrial.ondemand.com/api/v1/accounts -s 
bx target -g  -s

Then run:

cf services

or to get more detailed output:

cf services --json | jq '.[] | select(.state=="active") | {name,plan,type,space,state,created_at}'

4.5 Export the List to CSV (Optional)

Using jq to format for CSV:

jq -r '.[] | select(.state=="ACTIVE") | [.id, .service_name, .plan, .creation_time] | @csv' services.json > services_active.csv

4.6 Verify the Data

  • Check that the number of services returned matches the expected count from your internal catalog.
  • Ensure that each service instance has a non‑null id and service_name.
  • Confirm that the state field is ACTIVE for all entries.

4.7 Security Note

Never commit client_id or client_secret to source control. Store them in a secure vault such as SAP Secure Storage or an external secrets manager.

6. Verification Steps

  1. Run the CURL command for the token and confirm a 200 OK response with a valid access_token.
  2. Execute the service‑instances API call and confirm a 200 OK with a non‑empty JSON array.
  3. Cross‑check the service names and plans against your internal catalog or BTP Cockpit.
  4. Ensure no ERROR or FAILED states appear in the list.
  5. Optionally, run the CLI cf services command and verify the same services are displayed.

7. Next Steps

  • Integrate the API call into a monitoring dashboard to trigger alerts if a service becomes FAILED or DELETED.
  • Document any new service instances that need to be provisioned or decommissioned.

8. Troubleshooting

ProblemCauseFix
Token request returns 401 Invalid client ID/secret or missing accounts.subaccount.read scope. Verify credentials, regenerate client secret, and ensure scope is included.
Service‑instances API returns 404 Wrong sub‑account ID or region mismatch. Confirm the sub‑account ID in the URL and use the correct region endpoint.
No services returned All services are in DELETED state or you lack permissions. Check the service state via BTP Cockpit and adjust ACLs.
CURL fails with SSL error Local machine missing CA certificates for the region. Update /etc/ssl/certs/ca-certificates.crt or add -k for testing (not recommended for production).
cf services shows “FAILED” services only The CF CLI might be targeting a different space. Use cf target -s to switch to the correct space or run cf services --all.
